# Безопасность Mixback (этап 3)

Что защищено сейчас, чем это проверено и что остаётся на бэкенд (этап 4). Раздел «Ограничения» важен: у приложения пока нет сервера, и браузерное хранилище **нельзя** считать безопасным местом для чужих секретов.

## Что реализовано

| Угроза | Защита | Где / чем проверено |
| --- | --- | --- |
| **XSS** (внедрение скриптов) | React экранирует весь текст; в коде нет `dangerouslySetInnerHTML`; строгая CSP: `script-src 'self'`, без `unsafe-inline`/`unsafe-eval`, `object-src 'none'` | `vite.config.ts` (meta в production-сборке), `public/_headers`; E2E: CSP присутствует, основные сценарии не нарушают её, `<img onerror>` в правке не исполняется |
| **Подмена текста** (Trojan Source, невидимые символы, «двойники» имён) | `cleanText`: удаляет управляющие символы, символы смены направления (U+202A–202E, U+2066–2069), нулевой ширины, BOM; NFC-нормализация. Применяется ко всем текстовым полям до валидации | `lib/sanitize.ts`, `lib/schemas.ts`, юнит-тесты |
| **Загрузка вредоносного файла под видом аудио** | Проверка не только расширения и MIME-типа, но и **сигнатуры** файла (RIFF/OggS/fLaC/ID3/MPEG/ftyp); лимит 60 МБ; файл не публикуется, а лежит в IndexedDB и воспроизводится через `blob:` | `lib/audio/sniff.ts`, `UploadVersion`; E2E: `.mp3` с HTML внутри отклоняется |
| **Подбор пароля** | После 5 неудачных попыток вход блокируется на 60 с (429). Счётчик ведётся и для несуществующих адресов — по поведению нельзя узнать, кто зарегистрирован; тот же лимит у смены пароля и удаления аккаунта | `createLocalApi.ts`, тесты `account.test.ts`, E2E |
| **Утечка паролей из хранилища** | PBKDF2-HMAC-SHA256, 100 000 итераций, индивидуальная соль; сравнение хешей за постоянное время; пароль никогда не лежит открытым текстом и не попадает в Redux | `api/local/password.ts`, тесты |
| **Вечная сессия** | Токен действует 7 дней, просроченный удаляется; при смене пароля выдаётся новый токен, старый перестаёт действовать | тесты `account.test.ts` |
| **Подтверждение опасных действий** | Смена пароля и удаление аккаунта требуют текущего пароля; удаление проекта/правки — подтверждение в диалоге | тесты, E2E |
| **Нарушение прав доступа** | Роли проверяются на «сервере»: 401/403/404; чужой проект отвечает 404 (не раскрываем существование) | `createLocalApi.test.ts` |
| **Open redirect** | После входа возвращаем только на внутренние пути (`/…`, не `//host`, не `javascript:`) | `safeInternalPath`, тесты |
| **Небезопасные адреса медиа** | Адрес аудио — только `demo/<файл>` или `idb:<id>`; `http:`, `data:`, `javascript:`, `../` отклоняются | тесты |
| **Повреждённые/подделанные данные в localStorage** | Структура проверяется при чтении, несовместимые данные пересоздаются; ошибки хранилища не роняют приложение | `api/local/db.ts`, тесты |
| **Clickjacking / MIME-sniffing / утечка Referer** | `X-Frame-Options`, `frame-ancestors 'none'`, `nosniff`, `Referrer-Policy: no-referrer`, `Permissions-Policy` (в `public/_headers`); `<meta name="referrer">` | `public/_headers` |
| **Утечка данных между пользователями** | При выходе и удалении аккаунта всё состояние Redux сбрасывается | тесты |
| **Подсказка паролей** | Индикатор надёжности + политика (≥ 8 символов, буква и цифра, ≤ 72) | `lib/passwordStrength.ts`, `lib/schemas.ts` |

Доступность — тоже часть безопасности интерфейса: сообщения об ошибках не раскрывают лишнего («Неверный e-mail или пароль» одинаково для любого провала).

## Ограничения (честно)

Всё, что «серверное», сейчас выполняется в браузере пользователя, поэтому его можно обойти через DevTools. Это учебный стенд, а не защита данных:

- localStorage/IndexedDB доступны любому скрипту на этом origin и самому пользователю; токен сессии лежит рядом с данными.
- Лимит попыток входа хранится на клиенте и сбрасывается очисткой хранилища.
- CSP через `<meta>` не поддерживает `frame-ancestors`; полный набор заголовков действует только на хостингах с `_headers`/конфигом (не на GitHub Pages).
- `npm audit`: 4 moderate-уязвимости в dev-цепочке Storybook (`glob`/`minimatch`), в production-сборку не попадают.

## План на этап 4 (бэкенд)

1. Пароли: argon2id или bcrypt на сервере; политика и ограничение длины там же.
2. Сессии: короткоживущий JWT (или серверная сессия) в `HttpOnly; Secure; SameSite=Lax` cookie + защита от CSRF; refresh-токены с ротацией.
3. Rate limiting и блокировки на сервере (по IP и по аккаунту), единые сообщения об ошибках.
4. Валидация входа теми же zod-схемами, лимиты размера тела, загрузка файлов — проверка сигнатуры и перекодирование через ffmpeg, хранение вне корня сайта.
5. `helmet`, строгий CORS (только адрес фронтенда), заголовки из `_headers`, HSTS.
6. Авторизация на каждом ресурсе (владелец/участник), без доверия к `role` из клиента.
7. Секреты — только в переменных окружения; в репозитории `.env.example`; зависимости — `npm audit` и Dependabot в CI.
